# dsh-dblclick-bottom

DeepSeek Harness 聊天面板双击滚动插件。

- **下半区双击**：把会话记录平滑滚动到底部，并停在那里（不再被自动跟随打断）。
- **上半区双击**：平滑跳转到最近一条自己的消息，并把它停在视口顶部；连按则逐条向上回溯；已经到最早一条时直接滚到顶。
- **边界自动加载**：当向上跳跃会越过「已加载内容的顶部」时，自动点击宿主的「加载更早 / Load earlier」按钮加载更早历史，加载完成后再完成这次跳跃（单次手势最多加载 3 页）。
- **上半区双击 / 三连点**：上半区的向上跳转由原始 `click` 计数驱动，用「间隔」区分双击和三连点——两次靠近的点击（间隔 ≤ 360ms）在短暂宽限后向上走一条自己的消息；但若宽限内又落了第三次点击，则它**超车**前面的双击、直接进入「一口气到最前面」的激进模式：自动反复点击「加载更早」直到历史全部加载完，然后把滚动条直接停到会话第一条消息的位置。也就是说，快速三连点是「一次连续滑到顶」而不是「先跳到上一条再跳到顶」。

无配置项、无依赖，安装即生效。

## 效果对照

| 操作 | 行为 |
| --- | --- |
| 双击下半区（y > 72% 视口高度） | 平滑滚到底部 |
| 双击上半区（y < 28% 视口高度），视口未对齐任何自己的消息 | 平滑滚到最近一条自己的消息上方 |
| 同上，视口已对齐某条自己的消息 | 平滑滚到上一条自己的消息 |
| 已在最早一条自己的消息上 | 平滑滚到内容最顶部 |
| 上半区双击，但上方还有未加载的历史 | 自动加载更早历史（封顶 3 次），加载后完成跳跃 |
| 双击直接落在「加载更早」按钮上 | 交给宿主自己的点击逻辑，插件不干预 |
| 上半区两次靠近的点击（间隔 ≤ 360ms），之后无第三次 | 延迟约 360ms 后向上走一条自己的消息 |
| 上半区在宽限内落了第三次点击 | 超车前面的双击，反复加载「加载更早」直到历史全部加载完，然后平滑滚到会话最顶部（第一条消息） |

## 安装

### 从 GitHub 安装

```bash
dsh plugin --profile desktop add https://codeload.github.com/liren2272-hue/dsh-dblclick-bottom/tar.gz/refs/heads/main
```

### 本地链接安装

克隆或复制本目录后，把源码目录软链/引用到 profile：

```jsonc
// C:\Users\<you>\.dsh\profiles\desktop\package.json
{
  "dependencies": {
    "@local/dsh-dblclick-bottom": "link:C:/Users/<you>/Documents/dsh-plugins/dsh-dblclick-bottom"
  },
  "dsh": {
    "profile": {
      "bundles": ["@local/dsh-dblclick-bottom"]
    }
  }
}
```

然后在 profile 目录执行 `pnpm install` 重建链接，**重启桌面端**即可生效。

> Windows 下若 git 拉取 GitHub 报 `CRYPT_E_REVOCATION_OFFLINE`，给命令加 `-c http.sslBackend=openssl`。

## 实现要点

- 只监听 `[data-conversation-scroll]`，自动避开右侧栏副本（`[data-sidebar-right-panel]`），多实例时取面积最大的主面板。
- 目标行通过宿主的 `data-chat-flow-kind="user"` / `"steering"` 定位，所属 turn 行取 `[data-chat-turn]`。
- 滚动用原生 `scrollTo({ behavior: 'smooth' })`，并用 `scrollend`（缺失时定时器兜底）确认落点；若浏览器忽略平滑请求则立即写入。落点由「自己滚动」还是「用户/宿主滚动」决定是否二次校正，避免与阅读跟随打架。
- 分页控件按文案匹配（`加载更早` / `Load earlier` 等），并回退到包裹元素的 `*_older` class，避免 CSS module hash 变化。
- 上半区的「走一条」与「直冲最前」都由原始 `click` 计数驱动，用宽限窗口区分：两次靠近的点击（间隔 ≤ `DOUBLE_GRACE_MS`）先挂起一个延迟约 360ms 的 walk-up；若宽限内出现第三次点击，则取消 pending 的 walk-up、直接进入 `jumpToFront`，让快速三连点成为「一次连续滑到顶」，而不是「先跳到上一条再跳到顶」。两次慢速的点击不会误触发 walk-up（间隔超过宽限）。
- 「连点 3 次到最前」只统计落在上半区、且不落在交互元素/「加载更早」按钮上的原始 `click` 事件（2.5 秒窗口）；触发后进入 `jumpToFront`，反复点「加载更早」直到控件消失（封顶 60 页、每页超时 15 秒）。控件消失时宿主往往还在跑加载后的布局回流、会把滚动条重新钉在保留锚点（原「加载更早」所在行），因此 `jumpToFront` 不再用平滑滚动抢落点，而是等宿主回流稳定后强制把 `scrollTop` 写 0 并持续复写，直到宿主把这次外部写入识别为读者移动并释放锚点——这样第一次连点就直接停在最顶端，不需要再连点一次（修复了「连点后只停在加载更早位置、再来一次才到顶」的问题）。同时，若 `jumpToFront` 开始时控件因被超车的双击 walk-up 而处于 `disabled`（飞行中加载），它会先等待该页落地再接管，避免只停在半加载位置。

## 版本历史

- **1.4.0**：上半区的「向上走一条」与「直冲最前」改为由原始 `click` 计数驱动，用宽限窗口区分双击与三连点：两次靠近的点击延迟约 360ms 才走一条，宽限内落第三次点击则超车前面的双击、直接一口气到最前面（一次连续滑到顶）。原生 `dblclick` 的上半区分支改为空操作，避免与计数分支抢锁。回归测试相应改为用 `click` 驱动走一条/三连点，并新增「宽限内第三次点击超车 walk-up」用例。
- **1.3.1**：修复「先上半区双击（向上走一条）紧接着立刻三连点，只到上一条对话、要等一阵才行」的问题。根因是双击的 walk-up 若正处于加载更早历史的过程中（控件被禁用且标为加载中），此时三连点触发的 `jumpToFront` 在旧逻辑里会因控件未启用而提前收尾、只停在半加载位置。现改为：控件存在但处于 `disabled`（飞行中加载）时，`jumpToFront` 先等待该页落地、再接管继续把所有页拉到最顶，第一次连点即直达会话最前面。新增对应回归测试（控件在激进跳转开始时处于禁用态）。
- **1.3.0**：上半区连续点击 3 次以上（2.5 秒内）即直达会话最前面（阈值由 5 降至 3）；修复「连点后只停在加载更早位置、需再连点一次才到顶」的问题——`jumpToFront` 改为等宿主布局回流稳定后强制 `scrollTop=0` 并持续复写，第一次连点即停在最顶端。
- **1.2.0**：上半区连续点击 5 次以上（2.5 秒内）直达会话最前面，自动加载全部「加载更早」历史；新增对应回归测试。
- **1.1.0**：新增上半区「跳转到自己的消息」、连续向上逐条、越界自动加载更早历史、平滑滚动动画；新增回归测试。
- **1.0.0**：初始同步，仅支持下半区双击滚到底部。
